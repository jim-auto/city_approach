# CITY APPROACH

**「まあまあまあ」は、何回まで通じる？**

[![実プレイ：声かけ、4枚の会話フリップ、横スクロールの同行、相手別のゴールCG](./assets/demo.gif?v=fashion1)](https://jim-auto.github.io/city_approach/)

**[▶ ブラウザで遊ぶ](https://jim-auto.github.io/city_approach/)** · **[投稿用MP4](./assets/demo.mp4)** · [WebM](./assets/demo.webm)

街で声をかけ、相手の不安に4枚の返答で応える会話ゲーム。トークは無理に盛り上げるより、急かす・否定する・ごまかす返しを避けよう。連れ出したあとも会話は続く。相手に合う軽口はウケるけど、流しすぎると同行終了。二人でホテルに着いたら、相手ごとのゴールCGへ。

スマホ・PC対応。インストール不要。上のGIFは実際のブラウザ操作を約23秒に編集したものです。

## 主人公のタイプと身長

「ガチイケ・フツメン・オジ」と「低身長・高身長」を別々に選べる、計6通り。タイトルと街の上部にある2つのボタンで切り替え、どちらも保存される。初回はガチイケ・高身長。街・同行・ゴールまで身長を引き継ぎ、低身長では人物を少し小さく表示する。

相手ごとの好みは、服装・職業・現在の予定とは別に抽選され、近づくと街と会話で確認できる。

| 相手の好み | 効果 |
| --- | --- |
| フィーリング重視 | 6通りとも会話次第 |
| オジはNG | オジは身長に関係なく恋愛対象外 |
| オジも高身長ならOK | 高身長のオジは好印象、低身長のオジは対象外 |
| 高身長が好み | 高身長は有利、低身長でも会話で進める |
| ガチイケが好み | ガチイケは有利、それ以外でも会話で進める |
| オジが好み | 身長を問わずオジが有利 |

好みが合うと声かけの成功率・会話の初期安心感・誘いに必要な安心感が変わる。「NG」の対象は声かけで断られ、会話の点数を上げても誘いは成立しない。単なる好みの違いでは会話の選択肢を減点にせず、無難な返しで進める方針を保つ。ルールは `attraction.js`、選択の保存は `storage.js`。既存の難易度の保存値はタイプ選択として引き継ぐ。

`npm run test:types` で全36通りの相性と、Chromium／WebKitの6通りのタップ選択、街→会話→ゴールの引き継ぎ、身長切り替えによる相性の変化、NG判定、縦横の表示、選択保存を検証する。

男性3人の画像は内蔵画像生成ツールで制作。`assets/ai/player-cast.png` は左からガチイケ・フツメン・おじさんの3列、プロンプトは `assets/ai/player-cast-prompt.txt`。全員ジャケットなし。ゴールでは相手の頭身に合わせて男性の絵を選ぶ。頭身の高いバニーの一枚絵には、顔を小さくして体との比率を揃えた `assets/ai/player-goal-cast.png` を使用。元の3人を参照して内蔵画像生成ツールで制作し、プロンプトは `assets/ai/player-goal-cast-prompt.txt` に保存。`npm run test:difficulty` でChromium／WebKitのタップ選択、3人の描き分け、歩行、会話・CGへの引き継ぎ、縦横の切り替え、選択保存を検証する。

## ゲーム内容

- 名古屋駅と歌舞伎町を切り替えながら、NPCの行動サインを観察する。
- 声かけは「共感する」「状況いじり」「持ち物に触れる」「ユーモア賭け」から選択する。
- NPCの状態、余裕、警戒、きっかけを見て、有効なオープナーを選ぶ。
- フィールドは自由に歩いて相手を選ぶ。操作ボタンは声かけ4種類で、相手送り・スキップのボタンは置かない。
- 会話では相手の不安に合う返答を4枚のフリップから選ぶ。時間・友達・予算・警戒など11テーマを出題する。
- 4つの不安のうち3つ以上に応え、タイプと相性ごとの必要安心感を満たし、違和感60未満で最後の誘いが合うと同行へ進む。
- スマホ向けに縦横の画面へ対応し、会話の選択肢はブラウザ標準ボタンでタップを受け取る。
- 会話が成立すると横スクロールの同行ステージへ。二人で右へ歩き、ホテル到着でゴール（+100点）。
- 左右ボタン長押し・矢印/A/Dキー・画面タップで移動。遠景がゆっくり流れ、ホテルまでの距離と進捗を表示。
- 同行中は6回、うちホテル入口で3回、相手から「どこ行くんですか？」などの質問が来る。「安心させる」「冗談」「褒める」などの具体的なセリフを4枚のフリップから選ぶ。
- 「まあまあまあ」を連続すると不信感が20→55→100と上がり、3回連続で同行終了。説明すると不信感が25下がり、連続流し回数もリセット。
- ホテル前の行き先確認は流しても解決しない。相手が納得してからホテル到着になる。同行終了では到着ボーナスを得られず、連続記録もリセット。
- ホテルが各同行ステージのゴール。累計500点ではCITY CLEARも獲得でき、Bestとランク更新を狙って続行できる。

## 自動テスト（Playwright）

Node.js 20以上で実行します。テスト専用の依存関係で、ゲームの配信にビルドは不要です。

```bash
npm ci
npx playwright install --with-deps chromium webkit
npm test
```

テスト用HTTPサーバーは自動起動します。既存サーバーを使う場合は `SMOKE_URL` を指定できます。
`npm run test:smoke` で既存機能の回帰テスト、`npm run test:mobile` でスマホ向けテストのみ実行できます。

スマホ向けテストはChromiumとWebKitで、320×568、360×640、390×844、412×915、568×320、844×390を検証します。
街→会話→同行→ホテル→街への復帰をタッチで操作し、44px以上のボタン、文字のはみ出し・重なり、画面回転、ノッチ相当の余白をチェックします。
Chromiumではドラッグ、複数の指、タッチキャンセルも検証し、390px幅では全ルートを右ボタンの長押しで歩きます。
その他の到着テストはホテル近くの位置を使います。声かけのみ成功率を固定し、会話の選択とステージの操作は実際のタッチ入力です。
同行会話は6回の応対と行き先確認による成功、3回連続のごまかしによる同行終了と無報酬・街への復帰もタッチで検証します。
`npm run test:privacy` はGitの全履歴を調べ、個人ホームディレクトリの絶対パスが混入していないか確認する。画像生成の記録には相対パスを使う。

結果とスクリーンショットは `test-results/mobile/` に保存されます。実機ではなくブラウザエミュレーションです。

## スマホ対応

- 縦向き・横向きでタイトル、街、会話、同行、ゴール画面を配置し直す。
- 動的なブラウザバーとノッチ／ホームバーの余白に追従する。
- 指を離す、操作がキャンセルされる、別タブに移る、回転する際に移動入力を解除する。
- 会話では文字を読みやすく折り返し、返答の制限時間を5秒に設定する。
- 同行中の遠景はカメラが動く時だけ描き直す。

## 調査メモとゲーム反映

### 名古屋駅

- 中央通路が桜通口と太閤通口を結び、金時計・銀時計が待ち合わせ地点になっている。ゲームでは横長の中央コンコース、両端の時計、改札前の停止ポイントとして反映。
- 金時計周辺は待ち合わせ人数が多く、改札前・時計前で立ち止まる行動が起きやすい。ゲームでは「待ち合わせ系」「スマホ」「立ち止まり」のNPCを出し、成功率を少し上げる一方、人混みの距離感も判定する。
- 朝夕ラッシュは交通量が増えるため、昼は比較的判断しやすく、夕方寄りの混雑は失敗要因になる。ゲームでは名古屋駅を直線的な人流、NPCの規則的な移動で表現。

### 歌舞伎町

- 国内外から人が集まる繁華街で、夜はネオン、飲食・娯楽施設、観光客で密度が高い。ゲームでは暗い路面、ネオン看板、ランダムな群衆移動、ノイズペナルティで反映。
- 客引き・路上勧誘は新宿区の条例や警察の注意喚起対象。ゲームでは「夜の警戒」「声かけが多い」という会話行にし、違和感ゲージが上がりやすい設計にした。
- 単独よりグループ行動の防御力が高く、流れを止める声かけは失敗しやすい。ゲームでは「友達同伴系」に大きめの成功率マイナスを設定。

## 実装方針

- NPCは抽象化したtraitsをランダム合成し、traitsごとに成功率補正を加える。
- 名古屋駅は直線移動と停止ポイント、歌舞伎町はランダム移動と高密度の環境ノイズで差を出す。
- 16x16/32x32系のトップダウンドットを参考に、完全オリジナルの32x32 PNGを8色以内で作成。
- 実在人物の再現、特定の文化や個人への偏見を助長する表現は入れない。見た目ではなく「行動サイン」をゲーム判定に使う。

## キャラクターの基本デザイン

主人公は黒のマッシュヘアとTシャツ姿のガチイケを含む3人。女性NPCは20〜24歳の美容・デザイン・音楽・服飾の専門学生、大学生、地雷系、カフェバイトなど、私服・髪型・持ち物で描き分けた。近くの相手にはタイプ名と好みを表示する。

男性は `assets/ai/player-cast.png`、女性は `assets/ai/characters-fashion-*.png` とプリン髪の個別立ち絵を使用。4列×3行のアトラスから `characters.js` で会話用ポートレートと48pxの移動用スプライトを生成する。現在の私服と生成プロンプトは下記を参照。

## ホテルまでの街並み

`scenery.js` でコードから描画。名駅は夕焼けと落ち着いた店先、歌舞伎町は月夜・ネオン・濡れた舗道の反射で描き分ける。二層の遠景が異なる速度で流れ、商店街、街路樹のある広場、ホテル前へと景色が変わる。ホテルにはガラスの入口、庇、植栽、暖色の照明を追加。乱数は座標から固定して、歩行やリサイズ時に景色がちらつかないようにした。

## 不安に返すフリップ会話

会話は4つの不安と最後の誘いの全5ラウンド。警戒・時間・友達・予算・行き先・距離感・疲れ・断りづらさ・暇・髪と服・相手に合うノリの11テーマから、相手の状況に応じて出題する。4枚の具体的な返答を読み、相手の不安に合うフリップを選ぶ。具体的に応える返しに加え、無難に受け止める返しも毎回用意。ノリが違うだけでは違和感を増やさず、無難な返しだけでも同行に進める。カードの場所はシャッフルされ、それぞれに相手のリアクションが返る。画面には「減点なし」「好印象」を表示し、正解の連打より減点トークを避けることを重視する。3テーマ以上で安心を得て、タイプと相性ごとの必要安心感を満たし、違和感60未満で最後の提案が合うと同行へ進む。各ラウンドは属性に応じて12〜16秒、スマホのフリップは2列。台詞と選択肢は `conversation-flips.js`、進行と表示は `scenes/TalkScene.js`。

## 会話のタップ入力

会話フリップと同行会話の返答は、描画位置に重ねたHTMLの標準ボタンで入力を受け取る。見た目はPhaserのカード描画を使い、クリック、タップ、キーボード操作をブラウザに任せる。ボタンはキャンバス用のタッチ抑制の対象外に配置し、返答処理中は無効化、次の質問で有効化する。画面回転に追従し、シーンを離れると削除する。実装は `native-buttons.js`。

`npm run test:taps` で縦横4サイズ×Chromium／WebKit、全4カードの中央と四隅（計160箇所）を確認する。実際の会話進行、キーボード、シーン切り替え後のボタン削除も検証する。Chromiumでは指が少し動くタップも確認する。


## ラブホテルと属性の相性

ゴールはラブホテル。同行前のフリップと歩行中の会話で行き先を伝え、入口でも入るかどうか確認する。ラウンジへの誘いにはしない。外観にピンクのハートと `LOVE HOTEL` の看板を追加。

相手は全員20〜24歳の架空の成人キャラクター。職業・見た目・現在の状況を組み合わせて7タイプを判定し、初期安心感、警戒、選択肢ごとの加点、誤答時の違和感、同行に必要な安心感を変える。同じ軽口でも「暇なプリン髪大学生」は+34、急いでいる相手には無難な返しとして+16・違和感増加なしとなり、短い返答ならさらに好印象となる。専門学生は服や髪の話、友達といる相手は予定への配慮、慎重派は具体的な説明が得意な返しになる。無難な返しは安心感+16。相性による上乗せはあるが、無難な返しだけでも必要な安心感を満たせる。

専用のプリン髪大学生（21歳）は、黒い根元が伸びた金髪とゆるい私服で描き分け、各マップに1人出現する。既存40種類に加えた41番目の見た目として `assets/ai/character-prin-student-fashion.png` に保存。内蔵画像生成ツールを使用し、プロンプトは `assets/ai/characters-fashion-prompts.json`。

属性ルールは `encounter-rules.js`、会話の出題は `conversation-flips.js`。`npm run test:encounters` で属性別の効果差、全7タイプの無難な返しだけでの成立、7タイプ×縦横画面×Chromium／WebKitの操作を検証する。ブラウザでは慎重派に無難な返しだけを実際にタップして最後の誘いまで確認する。

## 初期難易度とゴール演出

初回起動は「ガチイケ・高身長」。タイプと身長の選択は次回にも引き継ぐ。ラブホテル到着時は大きな「ゴール！」の文字が弾んで現れ、紙吹雪、光、効果音でゴールを祝う。到着ボーナスは従来どおり+100で、一度だけ加算。端末で動きを減らす設定を使っている場合は、文字をすぐ表示し、点滅や紙吹雪は省く。

`npm run test:goal` で初期難易度、保存した設定、縦横画面の演出、得点の重複防止、再挑戦後の失敗で祝福が残らないことを確認する。

## ゴールの記念CG

ラブホテル到着時は、ベッド・枕・ベッドサイドの照明が見える客室背景に、主人公と実際に同行した女の子の高解像度立ち絵を重ねた記念CGを表示する。41種類の姿・色違いを引き継ぎ、縦画面は絵を大きく、横画面は絵と結果を左右に配置。回転時にも構図を調整する。客室背景は内蔵画像生成ツールで作成し、`assets/ai/bedroom-{rose,neon}.png`、最終プロンプトは `assets/ai/bedroom-prompts.json` に保存。

`npm run test:goal` はCGの実際の描画ピクセル、同行相手・配色の一致、画面回転、動きを減らす設定、再挑戦時の失敗画面への持ち越しも検証する。

## 相手ごとのホテル内コスプレCG

ゴール後は相手の姿に応じて、ホテル内でコスプレした記念CGを表示する。量販店の定番コスプレをイメージしたセーラー服、紺のスクール水着、体操服＆ブルマ、メイド服、ミニスカポリス、ナース服、バニーガールの7系統・11バリエーション。従来の4配色×10人とプリン髪大学生を引き継いだ計41種類で、全員20〜24歳の成人キャラクター。衣装ごとに本人のひとことも変わる。プリン髪大学生のゴール衣装は黒バニー。READMEの実プレイ動画も、この相手のバニーCGで締める。

室内はベッドが見えるローズ系とネオン系の客室2種類。`goal-costumes.js` で街のキャラと配色から衣装、台詞、部屋を決め、同行時に必要な配色の画像と部屋だけを読み込む。人物の透過部分を測って二人を配置し、広いスカートや帽子が切れないようにする。衣装はゴール画面でのみ使い、街と会話中は私服のまま。得点と同行中の行き先確認は従来どおり。

内蔵画像生成ツールで制作した画像は `assets/ai/costumes-retail-{original,pastel,street,chic,prin}.png` と `assets/ai/bedroom-{rose,neon}.png`。黒バニーは `assets/ai/costumes-bunny-prin.png`、生成プロンプトは `assets/ai/costumes-bunny-prin-prompt.txt`。衣装の最終プロンプトと参照画像は `assets/ai/cosplay-retail-prompts.json`（現在の客室背景は `assets/ai/bedroom-prompts.json`） に保存。

`npm run test:costumes` はChromium／WebKitで全41種類のCG、7系統・11バリエーション、2部屋、透過、絵の重複防止、相手と配色の一致、人物のはみ出し防止、台詞と得点を確認する。衣装一覧と各衣装のゴール画面は `test-results/costumes/` に出力。

## 相手の反応を読む同行会話

同行ステージは、相手の発言に対して4枚の具体的なセリフから返す会話ゲーム。ジャンプ、ハート拾い、水たまり、フィーバーは廃止した。左右ボタン・画面タップ・矢印／A・Dで歩き、道中3回、ホテル入口で3回話す。会話中は歩行が止まり、返答に制限時間はない。選んだセリフと相手の反応は3秒表示する。

行き先の確認の間に「声かけに慣れてる？」などの雑談と、相手ごとの関心事を挟む。暇な相手には軽口、専門学生には服や髪、慎重派には正直な説明、予定がある相手には短い説明などが合う。同じ返しでも7タイプで反応・加点が変わり、画面のヒントから考えられる。安心させる無難な返しでも進め、相性のよい返しは+18点、2回続くと追加+10点。「盛り上がり」と会話ボーナスを表示する。盛り上がりの最低値や得点でゴールを制限しない。

ホテル入口では「まだ迷ってる」→相手ごとの料金・帰る時間・友達・気分の迷い→最後の入場確認、と3往復する。最初の2往復だけでは入場が決まらない。最後に「今日は解散」を選ぶとゴールせず終了する。

「まあまあまあ」の連続では従来どおり不信感が上がり、3回で同行終了。行き先を確認し、相手も入ると決めて到着すると、相手ごとのコスプレCGと+100点の到着ボーナスが出る。4枚のフリップはスマホ縦横とも2列で、HTMLの標準ボタンからタップを受け取る。

台詞・タイプ別の効果は `escort-conversation.js`。`npm run test:escort` で7タイプの相性差、無難な返しの加点とゴール成功、連続加点、連続ごまかしによる終了、画面回転・タップ入力・CGへの接続を検証する。

## READMEのプレイ動画を作る

```bash
npm run demo:record
npm run demo:build
```

Playwrightが自然に出現したプリン髪の相手へ実際のキー入力・タップで声をかけ、会話からホテル客室のバニーCGまで録画する。声かけに失敗したテイクは通常のリロードからやり直す。ゲーム状態・成功率・得点は書き換えない。録画と区切り時刻は `test-results/demo/` に保存し、FFmpegで時系列の見どころを切り出す。生成にはFFmpegとNoto Sans CJKフォントが必要。

README用GIFはゲーム画面だけの480×800・10fps・ループ再生。投稿用MP4は1100×800・H.264・約23秒。WebMも同じ内容。MP4／WebMの左側の字幕は編集で加えた説明で、ゲーム画面は実際の録画。編集区間は `assets/demo.json` に記録する。Xへの投稿はMP4を使用できる。
